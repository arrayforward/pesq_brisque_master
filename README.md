# PesqBrisqueMaster — 画面 BRISQUE + 音频无参考质量评估 (Android)

面向 Android 10+ 的音画质量评估工具：通过 `MediaProjection` 定时截屏评估画面质量（BRISQUE），通过 `AudioPlaybackCapture` 直接录制系统播放的声音，用 **MOSNet** 和 **ITU-T P.563** 两个无参考模型输出 MOS 分。UI 全部使用系统原生控件（不依赖 AndroidX），四个 Tab 页：画面+音频、音频、日志、配置。

---

## 一、设计思路

### 1. 采集链路

| 采集对象 | 方案 | 原因 |
|---|---|---|
| 画面 | `MediaProjection` + `VirtualDisplay` + `ImageReader`（前台服务，类型 `mediaProjection`） | Android 唯一合规的全屏采集方式；每 100ms 取一帧，直接获得 RGBA 像素，双线性降采样到 512 宽后评分 |
| 声音 | `AudioPlaybackCapture`（`AudioRecord`，16kHz 单声道，匹配 USAGE_MEDIA/GAME/UNKNOWN） | 数字回路直接取系统混音输出，不经过麦克风/扬声器，无环境噪声干扰，适合横向对比不同 App 的播放音质 |
| 倒计时 | 先倒数 N 秒再采集 | 给用户从本 App 切换到目标 App 的时间；界面大数字 + 系统通知栏同步刷新，切走后也能看到 |

### 2. 评分算法与实现原理

#### 画面：BRISQUE（无参考图像质量评估）

原理：自然图像的 MSCN（均值减去、方差归一化）系数服从广义高斯分布，失真会改变这种统计特性。

1. 灰度化（0.2125R+0.7154G+0.0721B）
2. 计算 MSCN 系数：7×7 高斯核（σ=7/6，可分离卷积加速）求局部均值 μ 和局部方差 σ，`MSCN = (I-μ)/(σ+1/255)`
3. 对 MSCN 及其 4 个方向（水平/垂直/主对角/副对角）相邻乘积分别做 AGGD（非对称广义高斯）拟合 → 每尺度 18 维特征，2 个尺度（第二个尺度为 1/2 双三次降采样）共 36 维
4. 特征归一化到 [-1,1]（LIVE 数据集 min/max），送入 libsvm RBF 模型（770 支持向量）回归出 0~100 分（越低越好）

模型文件：`assets/brisque_svm.txt`（LIVE IQA 数据集训练）。已用官方样例图验证：4096×2160 自然照片得分 34.1（正常区间）。

#### 音频模型 1：MOSNet（深度学习语音质量模型）

结构：STFT 幅度谱 → 4 组 CNN（12 层 Conv2D，16/32/64/128 通道）→ 双向 LSTM(128) → Dense → 逐帧 MOS，全局平均得整段 MOS（1~5 分）。

实现：Keras 预训练权重 `cnn_blstm.h5` 离线导出为自定义二进制 `assets/mosnet_weights.bin`（4.7MB），**C++(NDK) 手写前向推理**（hamming 窗 STFT 512 点/hop 256 → 卷积 → BLSTM → Dense），不依赖 TFLite/Python，10 秒音频在手机上约 1~3 秒算完。

#### 音频模型 2：ITU-T P.563（单端无参考语音质量评估，官方参考实现）

电信标准中 PESQ(P.862) 的无参考版本：从信号本身提取发声特征（基音、LPC 包络、噪声/中断/机器人音检测等三模块）映射到 MOS-LQO（1~4.5 分）。输入要求 8kHz 窄带语音——本应用把 16kHz 录音经 31 阶 FIR 低通（3.4kHz 截止）后 2 倍抽取得到。官方 C 代码直接 NDK 编译为 `libp563.so`。

设备验证：干净语音 MOSNet=3.48 / P.563=4.10；音乐 MOSNet=2.32 / P.563=1.27（语音模型评音乐必然偏低，见"使用要求"）。

#### 辅助频谱指标

对整段录音给出客观参数（不构成综合分）：带宽（95%/99% 频谱滚降点）、底噪 SNR、动态范围、削波率、有效发声占比、平均电平(dBFS)。

#### 备用：PESQ（ITU-T P.862，全参考）

`libpesqjni` 已编译，`Pesq.measure()` 可直接调用。需要与播放内容完全一致的参考音频，当前界面流程未启用。

### 3. 工程取舍

- BRISQUE 每帧约需 0.3~0.5 秒，无法在 100ms 间隔内实时打分 → **采集与打分分离**：采集期只存灰度字节 + JPEG，结束后逐帧打分
- 帧图片存 `files/frames/frame_NNN.jpg`，供点击查看与另存；每次评估前自动清空
- 服务广播事件驱动 UI，Activity 整个生命周期保持接收器注册，切后台再回来进度不丢
- 截屏与录音失败会把完整系统错误堆栈上报到日志页

## 二、使用要求（重要：选对内容才能得高分）

两个音频模型都是**语音**模型，BRISQUE 是**自然照片**模型。评测内容越接近模型的训练域，分数越有意义：

| 评估对象 | 建议播放内容 | 典型分数区间 | 说明 |
|---|---|---|---|
| 音频 MOSNet | **真人语音**（新闻播报、有声书、通话录音） | 清晰语音 3~4.5 | 播放音乐时分数系统性偏低（约 2~3），不是 App 音质差，是模型不认识音乐 |
| 音频 P.563 | **窄带语音**（电话音质内容） | 清晰语音 3.5~4.3 | 同上，音乐约 1~2.5 |
| 画面 BRISQUE | **自然场景录像**（风景、人物实拍视频） | 清晰画面约 20~50 | UI 界面、文字、纯色块、动漫等屏幕内容会打到 80~110，属正常现象 |

**结论：本工具的分数适合"同一内容、不同 App/不同设置"的横向对比**（比如 A 音乐 App vs B 音乐 App 放同一首歌），不要把绝对分数当作内容本身的质量。

其他要求：

- 目标 App 必须允许被回放采集（大多数播放器允许；禁止的 App 录到的是静音，日志会提示"最大振幅 0"）
- 采集期间保持屏幕常亮、目标 App 在前台持续播放
- Android 10 及以上

## 三、功能详解

### Tab 1：画面 + 音频

完整流程：倒计时 → 同步截屏+录音 → 逐帧打分 → 统计 + MOS 评分。

- **开始评估按钮**：点击后弹出系统"屏幕录制"授权框，允许后进入倒计时
- **倒计时**：大号数字居中显示 + 通知栏同步，倒数期间请切换到目标 App
- **录制中**：大数字变为剩余秒数，进度条推进；每 100ms 截一帧（10 秒 ≈ 100 帧），同时录系统声音
- **统计区**：最高 / 最低 / 平均 / **去极值平均**（排序后去掉最高 5 个、最低 3 个再平均，抗偶发异常帧，最能代表整体水平）
- **逐帧列表**：每行 = 帧号 + 分数条 + 分数 + 质量标签（优秀<25 / 良好<40 / 一般<60 / 较差≥60，按分数着色）
- **点击帧行**：全屏查看该帧截图，可「另存为」到相册（`Pictures/PesqMeter/`）

### Tab 2：音频（长录音评估）

适合长时间评估目标 App 的播放音质，不截屏。

- 时长在「配置」页设置（5~600 秒）
- 每 10 秒为一个分段，实时滚动显示每段的 MOSNet / P.563 分数，结束给平均分 + 频谱指标

### Tab：本地视频文件评估

- 直接选择本地视频文件（无需投屏授权），按配置页设定的抽帧间隔（默认 200ms）抽帧做 BRISQUE 打分，逐帧展示 + 统计（最高/最低/平均/去极值平均）
- 同时解码视频音轨（MediaExtractor + MediaCodec → PCM → 重采样 16kHz）做 MOSNet + P.563 评分和频谱指标
- 帧图片同样可点击查看、另存

### Tab 3：日志

- 所有状态、进度、分段得分带时间戳滚动记录
- **故障诊断**：截屏授权失败、VirtualDisplay 创建失败、录音初始化失败等，完整异常类名 + 系统错误消息 + 堆栈都会打印在这里（同时写入 logcat，tag=`PesqMeter`）

### Tab 4：配置

| 配置项 | 默认 | 范围 | 说明 |
|---|---|---|---|
| 音频采集模式 | 自动 | 自动/回放/麦克风 | 见下方"音频采集模式" |
| 等待时长 | 5 秒 | 0~30 | 点击开始到正式采集的倒计时（切换 App 用） |
| 本地视频抽帧间隔 | 200 ms | ≥100 | 本地视频文件评估的抽帧间隔 |
| 画面录制时长 | 10 秒 | 5~60 | 每 100ms 一帧；时长越长帧越多、打分越久 |
| 音频录制时长 | 30 秒 | 5~600 | 长录音评估总时长 |

支持横屏；旋转屏幕不丢当前数据。

### 音频采集模式（三模式）

| 模式 | 说明 |
|---|---|
| **自动（默认）** | 优先系统回放采集（数字链路）；构造失败/初始化失败/录制 2 秒全程静音（目标 App 禁止采集）时**自动降级为麦克风模式**继续，结果标注实际使用的模式 |
| **系统回放采集** | 数字回路直采系统混音，保真最高；设备或目标 App 不支持时只报错不降级 |
| **麦克风** | 录"外放扬声器 + 环境"链路，任何手机可用；需外放音量 > 50%、环境安静 |

两种模式测的不是同一条链路，分数不要直接互比。即使截屏/录音权限缺失或设备不支持，App 也不会崩溃，完整错误打印到日志页。

## 四、使用步骤（详细）

### 画面+音频评估

1. 打开目标 App（如视频 App），找到要测的内容并开始播放，暂停也可以
2. 打开本 App → 首次使用会弹录音权限说明 → 确定 → 系统授权框点**允许**
3. （可选）到「配置」Tab 调整等待时长/画面录制时长
4. 回到「画面+音频」Tab → 点「开始评估」→ 系统弹"屏幕录制"授权 → 点**立即开始**
5. 倒计时开始，立即按 Home 键/手势切回目标 App，开始播放内容
6. 等待录制结束（通知栏可见剩余秒数），App 自动逐帧打分
7. 回来看结果：统计区四项、逐帧列表、音频 MOS 双分
8. 需要保存某帧证据图：点该帧行 → 「另存为」→ 相册 `Pictures/PesqMeter/`

### 长录音音质评估

1. 「配置」Tab 设置音频录制时长（如 60 秒）
2. 「音频」Tab → 点「开始音质评估」→ 授权 → 倒计时期间切到目标 App 播放
3. 每 10 秒出一个分段分（日志和状态栏实时滚动），结束自动给平均分

### 常见问题

| 现象 | 原因与处理 |
|---|---|
| 音频没有分数，日志显示"最大振幅 0" | 目标 App 禁止回放采集 → 换允许采集的 App，或改用外放+其他设备录音（本工具不支持） |
| 画面分数都在 80~110 | 屏幕内容对 BRISQUE 属域外内容，正常；看相对差异 |
| MOS 分很低但声音没问题 | 播放的是音乐，语音模型不适用；换语音内容验证 |
| 安装时卡住 | EMUI 会弹"未知来源安装确认"，需要手动点"继续安装" |
| 帧图片打不开 | 本次评估被新的评估清空了（每次开始前自动清空） |
